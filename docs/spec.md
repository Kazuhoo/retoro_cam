# retoro_cam 仕様書

使い捨てカメラを再現したiOSカメラアプリ。撮った写真はその場では見られず、24枚撮り切って現像に出すと、3日後に封筒に入って届く。

この文書がアプリの正（せい）です。ここに書かれていないことを実装で決める必要が出たら、勝手に決めずに確認すること。

---

## 1. コンセプトと守ること

- **撮る → 待つ → 受け取る**。撮った直後に写真を見せる機能は作らない。
- 70〜90年代の使い捨てカメラの手触り（巻き上げ、カウンター、フラッシュのスイッチ、封筒）を大事にする。
- 不便さには意味があるものだけを残す（見られない・待つ・1本を撮り切る）。見づらい・操作しにくいといった、意味のない不便は作らない。
- 機能を増やさない。迷ったら削る。

## 2. 対応環境・技術

| 項目 | 内容 |

| UI | SwiftUI（カメラのプレビューなど必要な部分だけ UIKit をラップ） |

| 課金 | StoreKit 2 |
| 広告 | Google Mobile Ads SDK（AdMob）＋ UMP SDK（Swift Package Manager） |

| 写真の保存 | Photos（追加のみの許可 `NSPhotoLibraryAddUsageDescription`） |
| サーバー | なし。すべて端末内で完結する |


## 4. 撮影画面

### レイアウト（横向き）
- 左：ファインダー（3:2、モックアップでは 507×338pt）。四隅にフレームの印、周辺を暗く、ガラスの淡い反射。
- 右上：残り枚数の窓（小）＋ 巻き上げダイヤル（横長）。その下に「巻き上げ　撮ったら、ダイヤルを右へなぞる」。
- 右中：状態表示（「撮影できます」／「ダイヤルを右になぞって巻き上げ」／撮り切ったら「現像」ボタン）。
- 右下：フラッシュのスイッチ（上に説明文）、写真アイコン、設定アイコン。
- 上端：左にカメラ名「SUNDAY 400 ・ 24EXP」、右に「▲ シャッター　音量ボタンを押す」。
- 下端：カメラのテーマのストライプと帯。
- 画面にシャッターボタンは置かない。

### ファインダー
- **フィルムの色をかけない素の映像**を出す。どう写るかは現像まで分からない。
- 日付もファインダーには出さない。

### シャッター
- 音量ボタン（上下どちらも）とカメラコントロール（対応機種）で撮る。`AVCaptureEventInteraction` を使う。
- `AVCaptureSession` が動いている間だけ有効。
- **シャッター音は常に鳴らす**（設定で消せない）。
- 巻き上げが済んでいないときは何も起きない（軽いハプティクスで知らせるのは可）。

### 巻き上げダイヤル
- 横長のホイール。**右になぞると巻き上がる**。左になぞっても戻らない。
- なぞった量に合わせて溝が流れ、**残り枚数の窓の数字が次の数字へじわっと回る**（数字の円盤が回るイメージ）。
- 回り切ったら巻き上げ完了。それ以上なぞると軽く跳ね返る。
- 一定量ごとにカチカチとハプティクス、巻き切りで少し強め。巻き上げ音あり（設定で消せる）。
- キーボードの右矢印でも巻ける（アクセシビリティ）。

### 残り枚数
- 新しいカメラは「24」で撮影可能な状態から始まる。
- 撮る → 数字はそのまま、巻き上げ待ち → 巻くと 24→23 へ回る → 撮影可能。
- 最後の1枚を撮ると「00」になり、巻き上げ不可。「現像」ボタンが出る。

### フラッシュ
- 縦のスライドスイッチ。つまみに丸い突起が4つ（2×2）。**下から上に上げるとON**。
- ONにすると横のランプがすぐ点く（充電時間なし）。
- **1枚撮るたびにスイッチは下に戻る**。続けて使うなら上げ直す。
- 説明文：「フラッシュ／上げるとON／1枚ごとに上げ直す」。
- カメラの機能はフラッシュだけ（インカメラ、ズーム、露出補正などは作らない）。

## 6. ロールと現像のルール

- どのカメラも **24枚撮り**。
- **持てるカメラは1台だけ**。撮り切るまで別のカメラに替えられない。
- 撮り切ったら「現像に出す」。途中で現像に出すことはできない。
- 現像には **3日**（72時間）かかる。現像に出した時刻＋72時間で届く。
- 現像に出したら、すぐ次のカメラを開けられる（待っている間も撮れる）。現像中のロールは何本あってもよい。
- 届いたらローカル通知を出す（現像に出した時点で72時間後の通知を予約する）。
- 通知の文言（案）：「写真が届きました。SUNDAY 400 の24枚です。」

### 現像に出す画面
- 確認：カメラ名、「24枚、撮り切りました。現像に出しますか？」、「写真は11月11日（水）ごろ、封筒に入って届きます。」「同じカメラは、新しく開ければまた使えます。」、ボタン「あとで」「現像に出す」。
- 出した直後：カメラが右へ滑って消え、封筒の枠に「11/11 お届け予定」。「現像に出しました／3日後、◯月◯日ごろに届きます。届いたらお知らせします。待っている間も、新しいカメラで撮れます。」ボタン「新しいカメラを開ける」。

### 現像画面
- 左上：使用中のカメラ（例：17/24、「あと7枚撮り切ると、現像に出せます」、無効の「カメラごと現像に出す」ボタン）。
- 左下：現像中（届くまでの残り時間と進み具合のバー）。複数あれば一覧。
- 右：届いた封筒（未開封／開封済み）。未開封には「新着」。
- 何もないときは空でよい。
- ヘッダーに「カメラを見る」「カメラに戻る」。

### 封筒
- 横長の封筒。上に**長方形のふた**（三角ではない）。シール（封）は付けない。
- 色はロールのカメラのテーマ。下にストライプと帯、右下にラベル（カメラ名・24EXP・撮影期間）。
- 紙のざらつきと明暗をつける。

### 封筒を開けて見る
- 未開封：大きな封筒。**ふたを上へなぞるとめくれ**、6割以上で指を離すと開く。途中なら閉じる。「ボタンで開ける」も用意。
- 開けた瞬間に**24枚をまとめて写真アプリへ保存**する（初回はここで写真の追加の許可を求める）。1枚目の下に「24枚を写真アプリに保存しました」。
- 写真は左右にスワイプしてめくる。指についてきて少し傾く。下に次の写真が重なって見える。上に「3/24」。最後は「これで全部です」。左右の矢印ボタンでもめくれる。
- 開封済み：封筒は出さず、写真の1枚目から表示する。
- 写真はアプリ内にも残す（現像画面からいつでも見られる）。

## 7. 写真

- **3:2**、**1536×1024px**（JPEG、品質0.88目安）。当時の写真屋さんのCD書き込み相当。
- 撮影直後に加工してアプリ内（Documents 配下、iCloudバックアップ対象）に保存。現像前は写真アプリに保存しない。
- 加工の順番：3:2に切り抜き → 縮小 → LUT → 粒子 → 周辺減光 → 光漏れ（ONのとき）→ 日付（ONのとき）。
- **日付と光漏れは、撮った瞬間の設定で焼き込む**（あとから設定を変えても、撮影済みの写真は変わらない）。
- 日付の形式：`'26 11 08`（年2桁、月、日）。オレンジ、右下、少しにじむ。
- 光漏れは画像の左右どちらかの端から入るオレンジ〜赤の光。位置と強さはランダム。
- 縦に持って撮ったら、写真は縦長で保存する（`AVCaptureDevice.RotationCoordinator` の `videoRotationAngleForHorizonLevelCapture`）。
- 縦長の写真の加工も、本物の使い捨てカメラと同じくフィルムの向き（横）で行う。シャッターである音量ボタンの側を上にした横向きで見たときに、日付が右下で正しく読める形に焼き込む。縦で見ると日付は**右上**で、**下から上へ**年・月・日の順に並ぶ（縦持ちの向きによらず固定）。
- 写真アプリに保存するとき、作成日時は**撮影日時**にする（`PHAssetCreationRequest` の `creationDate`）。
- 色味（LUT）と粒子・周辺減光の値：`tools/looks/README.md` と `Resources/LUTs/`。

- 設定に「購入を復元」。

## 9. 広告（AdMob）

- アンカー型アダプティブバナーを画面下端に表示する。高さはSDKが返す値を使う。セーフエリアの内側に置く。
- 表示する画面：カメラを選ぶ、現像、封筒を開けて見る（開封済みの写真も含む）。
- 表示しない画面：撮影画面、設定、カメラを買う、現像に出す、オンボーディング。
- 購入者には表示しない。
- 同意の流れ：
  - 初回起動のセッションでは広告を読み込まない。
  - 2回目以降の起動時に **UMP（必要な地域だけフォームが出る）→ ATT** の順で出し、終わってから広告を読み込む。
- 広告ユニットIDなどはリポジトリに直接書かず、`.xcconfig`（gitignore対象）から読む。開発中はテスト用IDを使う。

## 10. 許可

| 許可 | タイミング | 拒否されたとき |
|---|---|---|
| カメラ | オンボーディングの最後（「最初のカメラを開ける」を押したとき） | 撮影画面のかわりに「カメラが使えません。設定アプリでカメラをオンにしてください」と「設定を開く」（`UIApplication.openSettingsURLString`） |

## 12. オンボーディング（4ページ）

1. ようこそ：「撮って、待って、受け取るカメラ」／撮る→待つ→受け取るのアイコン
2. シャッター：「横に持って、音量ボタンで撮影」／画面にシャッターボタンはない

## 13. データモデル（案）

```swift
// SwiftData
@Model final class Roll {
    var id: UUID
    var cameraID: String          // "sunshine" など
    var createdAt: Date           // カメラを開けた日時
    var state: RollState          // .shooting / .developing / .delivered / .opened
    var sentAt: Date?             // 現像に出した日時
    var deliverAt: Date?          // sentAt + 72時間
    var openedAt: Date?
    @Relationship(deleteRule: .cascade) var shots: [Shot]
}

@Model final class Shot {
    var id: UUID
    var index: Int                // 1〜24
    var takenAt: Date
    var fileName: String          // Documents/Rolls/<rollID>/<index>.jpg
    var isPortrait: Bool
}
```

- 撮影中の状態（巻き上げ済みか、フラッシュ）は保存しなくてよい。起動時は「巻き上げ済み」で始める。
- 現在時刻は `Clock` プロトコル経由で取得し、デバッグメニューで時間を進められるようにする（3日待たずに確認するため）。
- 届いたかどうかは `deliverAt <= now` で判定する（通知はおまけ。通知が来なくても現像画面で届いている）。

## 14. 効果音・ハプティクス

- シャッター音（常に鳴る）、巻き上げのラチェット音、巻き切りのカチッ、フラッシュのスイッチ音、封筒のふた・袋を破る音。
- 巻き上げ：一定量ごとに `UIImpactFeedbackGenerator(.rigid)` 弱め、巻き切りで強め。

## 15. マイルストーン（実装の順番）

1. **カメラの土台**：プロジェクト設定（横向きのみ、iOS 17.2）、プレビュー、音量ボタンのシャッター、撮影、`FilmProcessor` で加工、アプリ内に保存
2. **ロールの仕組み**：SwiftData（Roll / Shot）、巻き上げダイヤル、回るカウンター、フラッシュのスイッチ、撮影画面のレイアウトとテーマ
3. **現像の流れ**：現像に出す、72時間、ローカル通知、現像画面、封筒を開ける、写真アプリへの保存、写真をめくる画面、デバッグ用の時計
4. **カメラと課金**：カメラを選ぶ／見る、StoreKit 2、購入の演出、購入を復元
5. **オンボーディングと設定**、許可を拒否されたときの画面
6. **広告**：AdMob、UMP、ATT、購入者は非表示
